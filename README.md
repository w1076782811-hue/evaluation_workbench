# 电商生图评测与生产提效工作台

一份可双击打开、也可发布到 GitHub Pages 的原生 HTML/CSS/JavaScript 工作台。无需安装依赖或启动后端。

**在线使用：[打开工作台](https://w1076782811-hue.github.io/evaluation_workbench/)**

代码仓库：[w1076782811-hue/evaluation_workbench](https://github.com/w1076782811-hue/evaluation_workbench)。分享给他人时，请使用上面的在线使用地址。

## 使用

- 本机：用 Chrome 或 Edge 打开 `index.html`。
- 网站：发布 GitHub Pages 后，将实际网页地址分享给其他人即可打开。
- 评分、图片、裁决和案例保存在各自浏览器；不会上传给站点作者，也不提供多人集中打卡或协作汇总。
- 十一个应用运行文件：`index.html`、`styles.css`、`workflow.css`、`data.js`、`eval-suite-data.js`、`pe-rules.js`、`pe-engine.js`、`task-engine.js`、`workflow-engine.js`、`workflow-view.js`、`app.js`。题库、规则库和引擎通过普通 script 加载，双击打开时不需要 fetch 本地 JSON。
- `assets/ref/` 与 `assets/gen/` 附带 44 张 PNG，分别对应 22 道题的参考图和结果图；现有 26 张用户更新示例、18 张编号占位图。机器分数和证据仍为预置演示，未随图片自动重新评测。
- Chart.js 4.6.1 从 CDN 加载；不可用时使用本地 SVG 图表。

## 导航与流程

**评测工作台**：首页、评测准备、评测任务、自动评测、评分复核、分歧裁决、评测报告、案例与改进。

**生产提效**：PE 优化。

推荐流程：选择题库或导入机器评测结果 → 查看自动建立的任务 → 确认评分标准、负责人和范围 → 点击开始评测 → 关联实际图片并独立盲判 → 处理分歧和阻断 → 查看任务范围内的报告 → 建立案例并回归。

批次是模型、数据集、评分规则与结果的容器；任务是关联批次的一项评测工作，有自己的范围、负责人和生命周期。一个批次可以拆成多个任务，评分仍属于批次与样本，不因任务切换而清空。

## 人机协同流程：分步实施

当前完成第 1 步“现有流程可视化”，详细进度见 [分步开发记录](workflow-development.md)。

- 自动评测页 `#/automation` 按样本与 L1–L8 展示机器已有分数、无法判断、失败和不适用项，可筛机器缺结果、已有结果和尚未完成人审的题。它读取既有结果，不调用模型、不伪造执行进度。

- 默认隐藏逐题机器分数。确认查看后，先保存曝光记录，再显示分数与证据。机器报告和实际同题机器对比也记录相关题的曝光；未锁定的初判不再计入独立一致率。自己完成独立初判后正常揭晓，仍保留该次初判资格；已保存的历史一致率不改写。换负责人姓名或刷新不能清除本地曝光。
- 曝光保存在 `wb_workspace_v2.workflow.machine_exposures`，由批次与样本定位；不新增账号、不验证本地填报姓名。既有草稿的曝光标记和复用原批次素材也纳入检查。曝光保存失败时不展示新机器答案。
- 这一小步仍要求全部适用维度人工复核。按项分工、局部人工提交、固定独立抽检、逐项合成与整批闭环将在后续步骤实施，页面明确显示“尚未接入”，不把旧人审记录当作已抽检。真实评测服务仍未接入。

## 本轮已实现

1. 八维检查点及 0/1/2 分边界例子，可在评测准备中编辑、评分时查看。保存初判后，本批规则冻结。
2. 评测集覆盖统计、组图与独立商品数量、运行/评测集/规则/PE 版本和生成条件记录。
3. 严格 JSON 导入校验、重复运行保护和同样本跨批次隔离；未运行成功或不确定的机器结果可以为 null，不伪装成 0 分。
4. 按品类、未评、已评、待裁决和机器不确定状态筛选，按编号定位；零匹配时不对旧样本继续评分。
5. 本地图片关联、刷新恢复、放大细节、位置标记、同组生成图对照。每张支持 PNG/JPG/WebP/GIF，最大 12MB；图片保存在 IndexedDB。
6. 独立盲判、适用维度分母、揭晓后锁分、保存去重。看过答案后不再计入独立一致率；重判原记录留档。
7. 用户确认的阻断口径：合规 L8 为 0 分，或存在 `source: human`、`confirmed: true` 的 P0 缺陷，先暂缓放行并进入裁决，不直接判废弃。
8. 裁决独立保存最终分数、最终缺陷、商用结论、实际裁决人及理由；不改写初判或初判一致率。解除严重阻断需明确确认与理由。
9. 报告可切换机器初评、人工初判、最终确认；人工结果实时进入报告，未经复核的数据不补成满分。缺陷热力图覆盖全部编码，含人体、跨图与合规问题；点击可返回样本。
10. 同题对照按评测集、规则版本及规则内容配对，展示实际可比项数。得分变化采用带正负号的相对百分比；对照分为 0 时不计算。
11. 标准正例、问题案例、规则澄清及跟进状态。标记已验证前，需新批次同样本的实际复核、相同评测集、明确说明且最终可用，无未解决分歧或阻断。
12. 真实人工计时，离页、切后台和保存自动暂停；只有同批样本全部完成且计时完整、填写旧流程基线，才计算耗时变化。
13. PE 升级为本地六步规则转写，分离商品事实、明确要求与拍摄建议；支持人话摘要、可编辑六段、来源核对、增量纠偏、完整提示词复制和实验快照。规则与使用边界见下节。
14. 深色模式、移动端、文本转义和本地旧数据迁移。

## 题库与任务流程

### 五套题与演示边界

`eval-suite-data.js` 按《评测题型数据集设计.md》提供五套独立题库，每套配一个批次与任务：

| 题套 | 名称 | 题量 | 重点 |
|---|---|---:|---|
| S1 | 白底主图基线验收 | 5 | 商品保真、结构与标识 |
| S2 | 场景图压力集 | 5 | 场景表现、光照与反射 |
| S3 | 模特图人体专项 | 4 | 人体结构、握持与遮挡 |
| S4 | 编辑指令集 | 4 | 编辑边界、未编辑区与接触关系 |
| S5 | 合规红线集 | 4 | 合规风险、阻断与人工确认 |

合计 22 道题、6 个品类、3 档难度。原始条目实际有 7 个图型名称：白底主图、场景图、模特图、编辑图、主图、详情图、对比图；页面按实际条目统计，不把文档概述中的“6 图型”写死。机器状态中有 3 条 `uncertain`。

机器分数、OCR/VLM 证据文字和置信度都是预置演示数据，不是本工具实际调用模型或识图得出的结果。文档中的 55%／30%／15% 是题库设计目标，不是已测得的人机一致率或准确率；分歧、裁决和人审统计以实际保存的记录为准，不预填人工结论。

配图现为用户更新示例与编号占位图混合。2026-10-30 首批更新 18 张（参考图 5 张、生成图 13 张），本轮继续补齐 8 张参考图；累计 26 张用户更新示例、18 张占位图。S1 白底题套的 10 张配图已全部替换，其他部分题仍需继续补齐。示例图与预置机器分数不一定匹配，不能将原有分数当作新图的实际评测结论。

图片目录与题号不变，内置图按 SHA256 内容版本加载，避免同名替换后浏览器继续使用旧图。图片类型逐文件登记，不再把所有 `assets/` 图片一律算作占位图。旧评分、裁决、任务及本机图片均保留；图片更新不会自动复算历史评分，使用当前素材时请重新核对。IndexedDB 中已手动关联的本机图片仍优先于内置示例。

缺陷字典补齐 `L7-02 场景错配`、`L7-04 卖点无证据`、`L8-02 功效暗示`，共 17 项。题目仍需依当前评分标准、适用维度和实际证据判定，预置描述不是自动裁决结果。

### 开始、暂停与范围

- 导入成功后同时保存批次、题目与任务，并打开任务详情；可从详情直接开始评测。重复 `run_id` 仍会被拒绝，不覆盖旧数据。
- 任务列表和详情显示实际范围、负责人、已评／总数、进度条、分品类进度和计时；当前批次也能点击查看详情。
- 状态每次依据实际题目与评分计算：空范围为草稿，有题未开始为可开始，开始后为进行中，未完成可暂停，全部保存评分后自动完成。不存一份与真实进度脱节的静态 `status` 或 `done`。
- 范围支持多选品类、多选图型，两类筛选取交集；空数组表示不限制该项。`limit: null` 表示不限，`limit: 0` 表示空范围，正整数在筛选后按原题目顺序取前 N 条。
- 开始任务后评测队列只在本任务范围内操作，默认定位未评题；暂停与继续保留草稿和实际进度。范围在首次开始后冻结，负责人和说明仍可按工作安排修改。
- 多个任务覆盖同一批次、同一题目时共享该题的已保存评分，各自按自己的范围统计；不会为制造进度复制评分或重复累计时间。
- 任务级耗时汇总范围内实际保存的人工计时。只有存在有效计时且还有待评题时才估算剩余时间；没有依据时不显示虚构时长。
- 支持按范围新建任务、修改负责人、导出任务范围内已保存的评分明细，以及归档／恢复任务。归档仅隐藏工作项，不删除批次、评分、裁决或图片；负责人是本地登记字段，不代表多人身份认证或权限隔离。

### 重复复核与任务报告

复制任务用于同范围另开一轮复核时，建立独立的 `repeat_review` 批次，保留原批次及其评分，不清空原记录。它复用现有题目和结果图，不会重新生图或调用模型；重复看过的材料不计入独立盲判一致率，也不能被当作新模型或新 PE 的生成效果。

任务报告按该任务选定的样本范围统计，并显示实际分母与各维度 n 值。暂缓放行的阻断样本单独统计，不纳入质量均分，不能用高平均分抵消阻断。人机比较只使用仍有独立资格、且双方存在有效 0/1/2 分的适用维度；`uncertain` 中的 null 维度不参与分母，有效非 null 维度可比较，不能把“无法判定”补成 0 分或当成分歧。

题套之间的报告用于查看覆盖与各自实际评分，不把不同评测集的均分差直接写成模型提升。同题、同规则及固定生成条件的版本比较仍沿用原有可比性检查。

## PE 六步规则转写

输入商品和画面要求 → 确认品类与版本 → 点击转写 → 核对摘要和内容来源 → 必要时编辑或纠偏 → 复制完整提示词到实际出图工具 → 保存实验并关联真实评测结果。

### 规则与来源

- 管线依次执行：术语化 → 具体化 → 意象拆解 → 否定转换 → 品类补全 → 兜底。引擎只计算规则，不访问网络、页面或存储。
- 当前规则包括 30 条意象、27 条术语、19 条模糊映射、12 条否定转换和 6 个品类：厨房小家电、3C 数码、美妆个护、食品饮料、服饰鞋包、家居日用。
- 原有 8 条模糊词以 `data.js` 的 `FUZZY_MAP` 为唯一正文来源，经适配添加参数和同义词；页面映射表与引擎读取同一套规则，其余条目按源文档补充。
- 规则依据：`自动化PE转写规则全集_V2.0.md`、`自动化PE规则文档_V1.0.md`、`PE引擎升级_开发任务书.md`。30 条完整意象来自 V1.0；三级兜底以开发任务书为准。
- 时间与季节等 D 类原文只规定光线和色彩，不为凑齐四维编造构图。缺失参数按用户要求、品类与默认规则继承，不自动加入节日道具。
- 光照、色彩、占比等属于经验建议，尚需固定模型、条件与样本后的真实生图评测。规则数量和输出完整不能证明实际效果提高。

### 优先级与保真

同类参数按“用户明确要求 → 意象建议 → 品类建议 → 兜底默认”处理。原始数值比例、明确光向和禁止项需核对；多个风格冲突会展示取舍，未识别说法会提示补充。

品类可以补充拍摄建议，但不能把“三层、304 不锈钢、6 个按键”等预设当成真实商品属性。结构、材质、颜色和标识按用户资料或实物参考保留；缺少事实时明确待确认。

兜底分三级：

1. **固定策略**：不额外添加第三方文字、标识或水印；保持明确主光及一致的阴影和反射。这是本工具的输出策略，不是通用法律结论；商品原有标识与合理辅助光需按实际要求保留。
2. **条件约束**：默认商品完整入画、保留安全边距；用户明确要求局部、特写或满版时，按条件让位。
3. **缺省值**：主体占比、画幅和留白只在没有更高优先级要求时补入，不能覆盖用户给出的横竖比例或特写需求。

### 核对、纠偏与复制

- 默认显示摘要与完整中文出图提示词阅读框，不必展开六段才能看正文。阅读框自动换行，长内容支持框内滚动、键盘移动与拖大；需要修改时仍可展开六段编辑，预览随手改和纠偏同步。
- “输入信息充分度”是按缺主体、未知说法和冲突等计算的启发式提示，包含原因；它不是理解准确率、模型置信概率或出图成功率。
- “太亮了／太暗了”每次相对上一轮明度调整 10%，初始基准为 100%；连续调亮为 110%、121%。主体过大／过小每次调整 10 个百分点。它们修改提示词，不直接改变已有图片，也不保证生成图达到相同的数值变化。
- 手动编辑内容会保留。纠偏涉及已手改的目标段时，提示用户直接核对和编辑该段，不自动覆盖。可撤销上次生效的纠偏。
- 主按钮“复制中文出图提示词”面向即梦、豆包等中文输入流程，包含六段和画面要求，不混入英文负面词。预览、主复制与新实验准备使用的输入共用一份文本。
- 英文负面提示是可选的排除项，页面先显示中文释义，英文原文与单独复制按钮默认折叠。仅在实际工具明确支持独立负面栏时按需使用；英文不天然比中文有效，也不保证生成结果符合要求。手指项只针对人物或手持场景，主体清晰不等于禁止背景虚化。
- “复制完整记录（含英文备查）”保留六段、系统约束与英文候选项，便于留档；不要把完整备查记录整段粘进普通出图输入框。页面不根据此选项宣称即梦、豆包的所有版本都支持或不支持独立负面栏。
- 更改原话、品类或版本后，保留旧结果供查看并标记过期；重新转写前不能继续复制、纠偏或保存成新实验，避免原话和结果错配。

### 版本与实验

新版引擎为 `pe-v2.0`，规则库为 `pe-rules-v2.0`，分别记录版本。`pe-v1.0`、`pe-v1.1`、`pe-v1.2` 保留原有算法和历史记录，不把新算法冒充旧版本。历史可用率标为演示配置；新版可用率留待实际评测，不预填提升数字。

“保存这次转写”留存当次原话、完整提示词、六段、约束、负面候选项、参数、品类及版本快照。新记录另存 `prompt_for_generation`（中文出图提示词）与 `output_profile: chinese_prompt`；`prompt_full` 继续作为完整备查记录。该标记只表示准备使用的输入形式，不代表已调用出图工具。

实际结果关联：新记录以 `prompt_for_generation` 精确匹配改写后的真实输入；旧记录继续匹配其原有 `prompt_full` 或历史六段，不迁移、不重算。只有同模型、同评测集、同评分规则和已记录生成条件的真实对照复核，且原话和改写后输入都匹配，才能展示这批配对样本的变化。若另用负面提示，应在实际运行条件中如实记录。

## 导入格式

在“评测准备”下载完整 JSON 模板，替换模板中的演示数据后再导入。每次使用新的 `run_id`，防止覆盖旧轮。

顶层结构：`{ "run": { ... }, "samples": [ ... ] }`。

运行必需信息：`run_id`、`model_version`、`dataset_version`、`standard_version`、`pe_version`、`seed`、`generation_params`、`purpose`、`sampling_strategy`。

样本包含：`sample_id`、`category`、`image_type`、`prompt_raw`、`evaluation_mode`、`applicable_dims`、`machine_scores`、`machine_defects`。组图另需 `group_id` 且至少两条同组证据；单图不能评 L6。

机器状态：`complete`、`failed`、`uncertain`。`complete` 的所有适用维度必须有 0/1/2 分，不适用项必须为 null；其他状态允许缺失机器结果。机器缺陷来源会固定为 machine，不可冒充人工确认。

`machine_evidence` 为可选证据对象数组，可提供 `layer`、`note` 等字段。没有证据时页面明确显示未提供，不自动编造 OCR 值、置信度或 VLM 理由。

图片通过复核页关联本地文件，导入 JSON 中的图片路径仅作文件名信息，不自动读取本机路径或访问远程图床。内置五套题仅使用随应用发布并在题库中登记的 `assets/` PNG；逐图内容摘要及“用户更新示例／编号占位”类型存于 `EVAL_SUITE_METADATA.image_assets`。不将外部导入路径作为可直接访问的图片地址。

## 数据与统计边界

- 新用户使用五套共 22 条演示题；旧 `SAMPLES` 的 12 条和 `TASKS` 的三个历史批次常量保留作兼容与参照，不删除旧用户的记录。历史雷达与趋势仍是演示快照，和本地实际人审分开。
- 人机一致率不等于机器准确率。裁决区记录可追溯最终判断，报告中的错放行观察只针对已裁决样本，不外推总体。
- 单题质量分按实际适用维度的权重重新归一。任务报告中阻断样本独立列出、不进入质量均分；合规阻断不能被高平均分抵消。
- 相对变化 =（新分数 − 对照分数）/ 对照分数 ×100%。它不是可用率、准确率或整体模型能力的变化。
- “最终确认”只纳入无待解决分歧的记录；暂缓补证不作为最终通过。
- PE 仍是本地规则转写，不是大模型生成。没有真实配对结果时不输出提升结论；规则建议和充分度提示不能代替看图复核。
- 本工具没有真实批量生图、模型调用、云端共享数据库或用户身份验证。实际人物姓名与裁决由使用者手工登记。
- “12 人天 → 1 人天”仍是目标，尚无实证。人工计时和手工登记的生成/评分耗时是本地测量记录，不代表已完成生产收益验证。

## 本地存储与迁移

保留约定键 `wb_reviews`、`wb_agreement_stat`、`wb_current_index`。草稿存于 `wb_review_drafts`，PE 草稿和纠偏状态存于 `wb_pe_draft`，主题存于 `wb_theme`。

`wb_pe_unknown` 保存当前浏览器中的未识别说法及次数；每次点击转写，同一个未识别说法只计一次，刷新、切页与纠偏不会增加次数。它是本地补库线索，不会汇总其他访问者的数据。PE 新增状态仍经统一存储适配层保存到 localStorage。

`wb_workspace_v2` 保存批次、任务、规则快照、裁决、历史初判、案例、PE 实验及效率记录。任务保存在 `tasks`，包含批次、范围、负责人、时间与暂停／归档标记；进度和状态实时计算。旧结构缺少 `tasks` 时，在首次渲染前补建对应工作项，保留原有批次、评分、草稿、裁决、案例、PE 实验及图片，不按历史写死数量伪造已完成任务。

旧无 run_id 的评分仍归入原默认演示批次，原分数和备注保留；新草稿按 run_id + sample_id 隔离。新题套按独立批次标识接入，不以题库更新覆盖同标识下用户已经保存的实际工作。

现有评测图片继续保存在 IndexedDB 数据库 `evaluation_workbench_images` 中，键包含批次、样本和图片类型；PE 升级不迁移或删除已有图片。file 与 HTTP/HTTPS 属于不同存储环境，切到新域名不会自动搬迁本机浏览器数据。清除浏览器站点数据会清除这些本地记录。
